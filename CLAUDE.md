# Trauma AI — контекст проекта (handoff)

Обновлено: 2026-07-06. Этот файл — полная сводка для продолжения работы в новой сессии.

## Что это

MVP AI-ассистента для врачей-травматологов и интернов в Украине. Соло-фаундер (Kolya), ограниченный бюджет. Цель текущего этапа — рабочий локальный прототип для валидации с практикующим травматологом (медицинским консультантом), НЕ production.

Корень проекта: `E:\Ai Agent in Medicine` (перенесён из `E:\trauma-ai` 2026-07-06). Исходный бриф: `files\claude-code-project-brief.md`; там же `files\trauma-ai-prototype.html` — дизайн-прототип фаундера.

Две функции:
1. **Клинический Q&A (RAG)** — врач задаёт вопрос, система отвечает ТОЛЬКО на основе базы знаний (протоколы, классификации) с обязательными ссылками на источники. Если данных нет — честно говорит «недостатньо даних», не выдумывает.
2. **Ассистент документации** — черновики выписных эпикризов, разделов истории болезни, разделов диссертаций по структурированному вводу врача. Не выдумывает клинические данные — ставит плейсхолдеры `[ВКАЗАТИ: ...]`.

Язык продукта (UI, промпты, документы, README) — украинский. Общение с фаундером — русский.

## Статус: каркас готов и проверен end-to-end (2026-07-06)

Реально проверено с живым Claude API:

Git инициализирован, первый коммит сделан. `.env` и `.venv` в `.gitignore`.

## Стек и структура

- Backend: Python 3.13 + FastAPI. Venv: `backend/.venv` (нативный Windows, НЕ WSL).
- LLM: Anthropic `claude-sonnet-5` (в `.env`, `CLAUDE_MODEL`). Обёртка `backend/app/llm/claude.py` передаёт только model/max_tokens/system/messages — Sonnet 5 отклоняет temperature/top_p (400).
- Векторная БД: ChromaDB локально (`storage/chroma/`), за интерфейсом `VectorStore` (`backend/app/rag/vector_store.py`) — для будущей замены на pgvector/Pinecone.
- Embeddings: `intfloat/multilingual-e5-base` (sentence-transformers). ВАЖНО: модели E5 требуют префиксы `query:` / `passage:` — инкапсулировано в `backend/app/rag/embeddings.py`.
- Frontend: React 18 + Vite 5 + Tailwind 3, экраны «Клінічний Q&A» и «Документи». Прокси `/api` → `:8000`.

## Как запускать

```powershell

cd "E:\Ai Agent in Medicine\backend"
.venv\Scripts\Activate.ps1
uvicorn app.main:app --reload --port 8000     # http://localhost:8000/docs, /api/health

# терминал 2 — frontend
cd "E:\Ai Agent in Medicine\frontend"
npm run dev                                    # http://localhost:5173
```

Ingestion уже выполнен. Повторять только при изменении `data/sources/`: `python -m ingestion.ingest --reset` (из backend/ в venv). Проверка ключа реальным запросом: `GET /api/health?deep=true`.

## Ключевые архитектурные решения

1. **RAG-grounded жёстко**: если `retrieve()` вернул 0 чанков — Claude НЕ вызывается вообще, отдаётся детерминированный ответ «недостатньо даних». Главная защита от галлюцинаций.
2. **Двухуровневая фильтрация тем** (важно понимать!): порог `RAG_MAX_DISTANCE=0.22` откалиброван замерами — релевантные запросы дают косинусную дистанцию 0.09–0.19, явно чужое (погода) 0.24+, но смежная медицина (кардиология ~0.19) ПЕРЕКРЫВАЕТСЯ с релевантными перефразами. Чистого порога не существует для этой маленькой модели. Поэтому: порог отсекает грубо чужое, а границу «травматология vs остальная медицина» держит правило 4 системного промпта (LLM отказывается). Таблица замеров — в docs/ARCHITECTURE.md. Настоящее решение (реранкер / e5-large / bge-m3) — в TODO.
3. **Цитаты детерминированы**: чанки нумеруются [1..N] в промпте, `citations[N-1]` ответа API соответствует ссылке [N] в тексте. Список источников строится из метаданных чанков, не из текста модели.
4. **Дисклеймеры детерминированы** — отдельное поле ответа API, не генерация моделью.
5. **Аудит**: каждый вызов LLM и каждый отказ → `logs/audit-YYYY-MM-DD.jsonl` (вопрос, источники, ответ, usage). PII пациентов не логируется; UI предупреждает врача не вводить ПИБ/даты рождения.
6. **Чанкинг** по токенам embedding-модели (~500, overlap ~80), не пересекает заголовки markdown → корректные метаданные `section`. Метаданные из YAML front-matter: `source_name`, `document_number`, `date`.

## Особенности ЭТОЙ машины (Windows, критично знать)

- **Avast MITM-ит TLS** (HTTPS scanning). OpenSSL 3.x отвергает Avast-сертификат (`Basic Constraints ... not marked critical`), падают HuggingFace/httpx. РЕШЕНО: пакет `truststore` (проверка через хранилище Windows) — инициализируется в `backend/app/ssl_setup.py` на старте `main.py` и `ingest.py`. Также `ssl_setup` удаляет инжектируемый Avast `SSLKEYLOGFILE`. На чистых машинах не мешает.
- Python: `py -3.13` (нативный `python` в E:\ сломан). Venv уже создан: `backend/.venv`.
- Node 20 / npm 10, зависимости фронтенда установлены.
